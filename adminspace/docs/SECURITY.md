# Security

What AdminSpace protects, against whom, how, and what remains open. Controls listed here are implemented in
the code referenced and covered by the tests named; see `docs/TESTING.md` for how to run them. No external
security audit or penetration test has been carried out.

## Assets and trust boundaries

| Boundary                                                                                                 | Who is on the other side                                                                              | How it is authenticated                                                                                  | Notes                                                                                                   |
| -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Back office (`/`, `/o/**`, `/admin/**`, `/account`)                                                      | Administrators in browsers                                                                            | Password (argon2id) + optional/forced TOTP, server-side session cookie                                   | Public, behind TLS (see `docs/DEPLOYMENT.md`)                                                           |
| Admin API (`/api/**`, `/oauth/**`, `/white-label/**`)                                                    | WorkAdventure play and back                                                                           | `ADMIN_API_TOKEN`, compared in constant time; Room API keys for `/api/room-api/authorization`            | **Keep private**: reachable only from WorkAdventure's network; the production proxy refuses these paths |
| AdminSpace → pusher (`/rooms`, `/message`, `/room/refresh`, `/global/event`, `/ws/admin/rooms`)          | WorkAdventure's pusher                                                                                | `ADMIN_API_TOKEN`; HS256 JWT signed with `ADMIN_SOCKETS_TOKEN` (1 h, room-scoped) for the websocket      | URLs set by superadmins only                                                                            |
| AdminSpace → map-storage `/maps`, map reachability checks                                                | WorkAdventure map-storage, map hosts                                                                  | map-storage bearer token                                                                                 | Map checks refuse private/loopback/link-local hosts other than the configured WorkAdventure hosts       |
| Database                                                                                                 | AdminSpace only                                                                                       | PostgreSQL credentials                                                                                   | Internal network only in production                                                                     |
| Component files for players (`/wa/worlds/{id}/collection.json`, `/wa/assets/**`)                         | WorkAdventure players' browsers                                                                       | none (public by design: players load them cross-origin)                                                  | Read-only; collection lists only installed components; assets served only for published versions        |
| Onboarding links (`/register/verify`, `/invite`, `/reset-password`)                                      | People holding an emailed link                                                                        | 256-bit single-use token in the query string, only its SHA-256 stored                                    | `Referrer-Policy: no-referrer`; confirmed by POST (mail scanners only GET)                              |
| AdminSpace → SMTP server                                                                                 | The configured mail relay                                                                             | `SMTP_URL` credentials                                                                                   | Optional; without it nothing is pretended to be sent                                                    |
| Integration Center callbacks and webhooks (`/integrations/oauth/*/callback`, `/integrations/webhooks/*`) | People's browsers; Slack, GitHub, GitLab                                                              | Session + single-use OAuth `state`; signatures (Slack v0 HMAC, GitHub HMAC-SHA256, GitLab secret token)  | Public; raw-body verification, replay windows, de-duplication (`docs/INTEGRATIONS.md`)                  |
| Automation API (`/automation/v1/*`)                                                                      | Zapier, n8n, scripts                                                                                  | Bearer automation tokens (SHA-256 stored, scoped, revocable), acting with their creator's current rights | Public; per-token and per-address rate limits; every call audited                                       |
| AdminSpace → providers and webhook destinations                                                          | Google, Microsoft, Slack, GitHub, GitLab, Notion, Trello, Miro, Spotify; URLs typed by administrators | OAuth tokens (sealed); webhook URLs (sealed); Standard Webhooks signatures                               | Destinations typed by people go through the SSRF guard (`integrations/guardedRequest.ts`)               |

Data held: back-office accounts, organization data, members (WorkAdventure identifiers, emails, names,
visit-card URLs), tags, bans (identifiers, IP addresses), reports (free-text comments), audit logs (actor,
IP), pseudonymised analytics, recording events, third-party secrets (sealed).

## Rate limits (defaults; `0` disables)

| Variable                                  | Default                 | Scope                                                                                    |
| ----------------------------------------- | ----------------------- | ---------------------------------------------------------------------------------------- |
| `RATE_LIMIT_LOGIN_PER_IP`                 | 30 / 15 min             | login attempts per client IP                                                             |
| `RATE_LIMIT_LOGIN_PER_ACCOUNT`            | 10 / 15 min             | login attempts per targeted account (pseudonymised key)                                  |
| `RATE_LIMIT_MFA_PER_IP`                   | 30 / 15 min             | second-factor attempts per client IP (plus 10 per pending session)                       |
| `RATE_LIMIT_SETUP_PER_IP`                 | 10 / hour               | first-run setup                                                                          |
| `RATE_LIMIT_SENSITIVE_PER_ACCOUNT`        | 20 / 15 min             | password, email and 2FA changes                                                          |
| `RATE_LIMIT_ADMIN_API_PER_MINUTE`         | 600 / min               | Admin API per client IP (WorkAdventure is a trusted, high-volume caller)                 |
| member export                             | 10 / 15 min per account | bulk CSV/JSON export                                                                     |
| `RATE_LIMIT_REGISTRATION_PER_IP`          | 10 / hour               | public registrations per client IP                                                       |
| `RATE_LIMIT_PASSWORD_RESET_PER_IP`        | 10 / hour               | password reset requests per client IP                                                    |
| `RATE_LIMIT_INVITATIONS_PER_ORGANIZATION` | 200 / hour              | invitations sent by one organization                                                     |
| `RATE_LIMIT_AUTOMATION_PER_TOKEN`         | 60 / min                | automation API calls per token (plus 300 / min per client address before authentication) |

Behind a reverse proxy, set `ADDRESS_HEADER`/`XFF_DEPTH`, otherwise every client shares the proxy's address
for rate limits, IP bans and audit entries.

## Credential rotation

| Credential                                                               | Rotation                                                                                                                                                                       |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ADMIN_API_TOKEN`                                                        | Set the new value in WorkAdventure and AdminSpace, restart both (`docs/OPERATIONS.md`, Token rotation)                                                                         |
| Map-storage API token                                                    | Change it in map-storage, then in Control Center › Instance settings (sealed at rest); failed jobs can then be retried                                                         |
| `SMTP_URL` password                                                      | Change it at the mail provider, update the env file, restart; Control Center › Email shows the next deliveries                                                                 |
| `APP_SECRET`                                                             | Not rotatable in place: it seals TOTP and third-party secrets (re-enrolment needed); keep it in the secret store                                                               |
| Room API keys, invitations, links                                        | Revoke from the organization pages; tokens are single use or expire                                                                                                            |
| Integration provider secrets (`*_CLIENT_SECRET`, `SLACK_SIGNING_SECRET`) | Rotate at the provider, update the environment, restart; connections keep working (tokens are not tied to the client secret, except Slack's signing secret for the Events API) |
| Webhook signing and receiver secrets, automation tokens                  | "New signing secret" / "New secret" in the Integration Center (shown once); revoke tokens from the Automation API page                                                         |

## Dependency status (npm audit, 2026-10-23)

- `nodemailer` is pinned to 10.0.15 (the 7.x line had high advisories); evaluated alternatives: a hand-written
  SMTP client (more risk) or a paid email API (new external dependency); SMTP works with any provider.
- Production dependencies: 0 critical, 0 high, 2 moderate — `ts-deepmerge` (prototype method override, DoS)
  through `@anatine/zod-openapi`, used by WorkAdventure's vendored schemas at module load with static input
  only (not reachable with request data). No upstream fix available.
- Development dependencies: 9 more (vitest, drizzle-kit/esbuild dev server, SvelteKit's `cookie` — low).
  They are not in the production image except `cookie` (cookie names here are constants).

## Known risks and open items

- **No external audit or penetration test.**
- **Admin API exposure is a deployment property:** it must stay on a private network; the production compose
  blocks it at the proxy, other deployments must do the same.
- **Superadmins are fully trusted:** they set the pusher and map-storage URLs that receive `ADMIN_API_TOKEN`
  and the map-storage token.
- **Back-office SSO is not implemented** (no OpenID Connect/SAML for administrators). Password reset by email
  and invitations need `SMTP_URL`; without it, invitation links are shown to the inviter (to share by another
  channel) and superadmins reset passwords.
- **Platform administrators remain trusted operators:** without email delivery, a platform password reset
  still shows a temporary password (the only recovery path); it is recorded in the organizations' audit logs.
  Taking down an abusive organization's files is done by suspending the organization (files and collections
  stop being served); there is no per-component takedown yet.
- **No per-organization fairness in the job queue** (global concurrency 4) and **no rate limit on the public
  `/wa/` files** (immutable, cached by browsers for a year); a CDN in front of `/wa/` is the mitigation.
- **Registration discloses taken organization slugs** (they are public in WorkAdventure URLs anyway) and, in
  "open without verification" mode only, whether an address has an account (rate limited).
- **Component files are public by design:** anyone who knows a world id can read its collection (names and
  images of installed furniture, no personal data); organizations should not upload confidential images.
- **Organization uploads are validated automatically, not reviewed:** they are visible to that organization
  only; the platform pack is the only content shown to every organization.
- **No row-level security in PostgreSQL:** isolation is enforced by the application (one policy, scoped
  queries, composite foreign keys) and tested at the HTTP and service levels; see
  `docs/ENTERPRISE_ARCHITECTURE.md` for the evaluation.
- **Erasure limits:** active bans keep the identifier (legitimate interest, documented on the page); report
  comments are kept verbatim; erasure applies per world.
- **Map reachability check:** resolve-then-fetch leaves a DNS-rebinding window (the check only warns and the
  fetch is GET without credentials).
- **Audit log is not tamper-evident** (no hash chain or WORM storage).
- **WorkAdventure-side behaviours** affecting enforcement are listed in `docs/INTEGRATION.md` §0.

Report vulnerabilities privately to the maintainers of this deployment; do not open public issues.
