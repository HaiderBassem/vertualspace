Mocks are used only where named: the pusher client tests use a local fake HTTP server, the live-kick tests a
local fake websocket server, the domain verification tests an injected DNS resolver, `enterprise.db.test.ts` a
local fake map-storage, and the end-to-end run an SMTP sink and a fake map-storage with an outage switch
(`tests/e2e/support/fakes.ts`). Everything else runs against real PostgreSQL. The fakes implement only what
AdminSpace calls (GET/PATCH of WAM files, `POST /upload`); the live components scenario checks the same calls
against WorkAdventure's real map-storage.

Integration Center (unit and contract tier): `integrations.pure.test.ts` (authorization URLs with state and PKCE S256 per
provider, token exchanges and refreshes against a mocked fetch, error mapping, webhook signatures with the published test
vectors of Standard Webhooks, Slack and GitHub and vectors computed with openssl for Notion and Trello, Slack/Discord/
Teams/webhook payloads, calendar and activity mapping, SSRF guards, delivery classification) and
`integrations.db.test.ts` (OAuth state single use and expiry, sealed tokens, refresh lease and rotation, the Admin API
calendar and presence endpoints parsed with their contract, events to deliveries to jobs to a real local HTTP receiver
with Standard Webhooks signatures, retries and 410, the automation API, inbound GitHub/GitLab/Slack webhooks, people
leaving, isolation between organizations, retention). The only mock is the providers' APIs
(`setProviderFetch`, `src/lib/server/integrations/http.ts`); deliveries reach a real HTTP server on 127.0.0.1 allowed
with `INTEGRATION_ALLOWED_PRIVATE_HOSTS`. End to end: `integrations.spec.ts` (honest "Not configured" states, setup
steps, refused private addresses, automation token lifecycle, Admin API without calendar capability) and the authz and
axe rows of the new pages.

Room sizes and the map-storage webhook (unit and contract tier): `roomSizes.db.test.ts` (reading sizes, dry runs
and resizes, refusals per status, rooms from templates at a chosen size, bulk resize jobs retried on 5xx and not
on 4xx, the "Create an office" wizard and its doors), `mapStorageWebhook.db.test.ts` (authentication, ignored
calls, registration, idempotency and concurrency, `/api/room/sameWorld`, deleted maps) and `office.pure.test.ts`
(door placement on the built-in templates, exit areas parsed with a copy of WorkAdventure's `AreaData`), against
the fake map-storage of `tests/support/fakeMapStorage.ts` (`/upload`, `/resize`, JSON Patch).

Who's in and employee profiles (unit and contract tier): `presence.pure.test.ts` (status mapping, report lifetime and
staleness, duplicates, grouping by world and room) and `presence.db.test.ts` (`POST /api/presence/report` through the
router: token, 400 and 413, capability, replacement per pusher, out-of-order and expired reports, purge, play URL
resolution, isolation between organizations and workspaces, "online now"); `profiles.pure.test.ts` (reporting loops,
fields, CSV columns) and `profiles.db.test.ts` (manager rules, concurrent changes, sharing across worlds, reporting
lines, department filter, CSV import and export, erasure). End to end: authz rows for `/o/{org}/presence`, its JSON view
and the profile action, and the axe row of the page.

## Isolation

- Unit and contract tests create their own organizations (`contract-test-*`, `retention-test-*`, ...) and
  delete them; retention runs are scoped to the test's own worlds.
- Database lifecycle and end-to-end runs create `adminspace_(mig|bkp|rdy|e2e)_<random>` databases and drop
  only those (name checked against the pattern).
- The live test uses its own `adminspace_e2e` database and a disposable Docker project (`wa-test`).
- `enterprise.db.test.ts` creates `ent-test-*` organizations and accounts and restores the instance settings it
  changes; the live components scenario creates a `live-*` organization, deletes it and the map-storage directory
  it uploaded, and restores the instance settings.

## Not covered

- Real ACME certificate issuance (needs public DNS).
- The GitHub Actions workflow itself (no remote configured); its steps were run locally.
- Load and soak testing beyond `scripts/perf-measure.ts` (20 clients, one machine); multi-instance deployments
  beyond the shared rate-limit store and the shared job queue.
- Live tests are not part of CI (they need Docker Hub images and ports 80/4100).
- Manual accessibility review with assistive technologies (axe covers automated rules only).
- WorkAdventure's map editor in a browser showing AdminSpace furniture (the collection format is checked against
  WorkAdventure's schema, and the WAM changes against the real map-storage, but no browser test opens the editor).
- A real SMTP provider (the sink accepts everything; TLS and authentication against a provider are untested).
